# 01. Серверное окружение и первичная карта системы

## 1. Назначение

Первичная карта legacy-системы Japandetali.ru для дальнейшего reverse engineering.

Цель — определить основные компоненты, точки входа, интеграции и реальные источники данных.

## 3. Основные части проекта

* `bitrix/` — ядро Bitrix
* `catalog/` — каталог
* `search_parts/` — поиск запчастей
* `search_vin/` — VIN-поиск
* `importvin/` — дополнительная VIN-логика
* `ajax/` — кастомные AJAX endpoint'ы
* `local/` — кастомный PHP-код
* `personal/` — личный кабинет
* `stock/`, `store/` — связанные с магазином разделы

Основная кастомная логика Bitrix находится в `local/php_interface/`.

Ключевой файл:
`local/php_interface/init.php`

## 4. Поиск запчастей

Кастомный компонент:
`bitrix/components/znikolaj/searchparts/`

Источники поиска:

1. собственный каталог Bitrix;
2. Adeo;
3. Mikado;
4. Autokontinent.

Связь VIN-поиска с каталогом пока отдельно не исследована.

## 6. Каталог

Основной каталог:

* IBLOCK_ID: `11`
* название: `Основной каталог товаров`
* тип: `1c_catalog`

Каталог заполняется через механизм 1С / CommerceML.

## 7. 1С

Стандартная точка обмена:

`/bitrix/admin/1c_exchange.php`

Реальные отчёты обмена находятся в:

`upload/1c_catalog/Reports/`

Обмены подтверждены ежедневно, примерно в 23:00.

04.09.2026:

* 23:00:07 — import
* 23:01:57 — import
* 23:02:13 — offers
* 23:03:08 — prices
* 23:04:02 — rests

Все операции завершились успешно.

`rests` содержит:

`СодержитТолькоИзменения="true"`

То есть остатки передаются инкрементально.

Для `import/offers/prices` режим полной или инкрементальной передачи пока не установлен.

## 8. Подтверждённая карта связей

**1С → CommerceML → Bitrix → каталог**

**Поиск запчастей → собственный каталог + Adeo + Mikado + Autokontinent**

**VIN-поиск → ACAT**

Эти три цепочки рассматриваются отдельно. Связь между VIN-механизмом и каталогом пока не подтверждена.
