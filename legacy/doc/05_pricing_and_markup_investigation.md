# 05. Ценообразование и наценки

Дата: 2026-08-15

## 1. Назначение

Зафиксировать, как в legacy формируется конечная цена найденной запчасти.

Здесь рассматриваются только правила цены и наценки. Источники товаров и поиск описаны в `03`, добавление в корзину — в `04`.

## 2. Внешние поставщики

Для внешних поставщиков цена рассчитывается через `getPrice()`:

```php
getPrice($price, $market)
```

Наценки читаются из инфоблока Bitrix `IBLOCK_ID = 14`.

Формат элемента:

```text
market=percentage
```

Текущая конфигурация:

| Поставщик     | Наценка |
| ------------- | ------: |
| Adeo          |      0% |
| Mikado        |      3% |
| Autokontinent |     10% |

## 3. Формула

```text
final_price = source_price × (1 + markup / 100)
```

Примеры:

```text
Adeo:          source × 1.00
Mikado:        source × 1.03
Autokontinent: source × 1.10
```

После расчёта цена форматируется до целого значения с пробелом между тысячами.

## 4. Собственный каталог

Для товаров собственного каталога используется:

```text
CATALOG_PRICE_1
```

Цена не проходит через `getPrice()` и наценки из `IBLOCK_ID = 14` к ней не применяются.

## 5. Передача цены в корзину

Цена внешнего товара формируется на этапе поиска и передаётся дальше через `data-json`.

`/ajax/add.php` принимает эту цену и сохраняет её в корзине как:

```text
CUSTOM_PRICE = Y
```

Повторный расчёт цены поставщика на этом этапе не выполняется.

Детали механизма корзины описаны в `04`.

## 6. Особенность legacy

В `getPrice()` обнаружена потенциальная проблема области видимости `$persents`: функция использует переменную, которая не передаётся ей аргументом и не объявлена через `global`.

Поэтому:

* конфигурация наценок подтверждена;
* код расчёта найден;
* фактическое runtime-применение 3% и 10% требует отдельной проверки.

Это характеристика legacy, а не требование новой системы.

## 7. Что установлено

✓ Наценки хранятся в `IBLOCK_ID = 14`
✓ Текущие значения: Adeo 0%, Mikado 3%, Autokontinent 10%
✓ Формула расчёта определена
✓ Собственный каталог использует `CATALOG_PRICE_1`
✓ Цена внешнего товара передаётся в корзину как custom price

## 8. Что не установлено

[ ] Проверено ли фактическое runtime-применение наценок
[ ] Есть ли дополнительные скидки/наценки на этапе заказа
[ ] Есть ли другие механизмы изменения цены
[ ] Может ли 1С или cron перезаписывать цены

## 9. Правило исследования

Исследование выполнялось в read-only режиме.

Изменения production-кода, цен, корзин и данных не выполнялись.
