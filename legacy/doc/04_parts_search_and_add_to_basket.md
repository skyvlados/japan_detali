# 04. Добавление результата поиска в корзину

Дата: 2026-08-15

## 1. Назначение

Исследовать, как результат поиска запчасти попадает в корзину.

Основная цепочка:

```text
результат поиска
    ↓
выбор количества
    ↓
GET /ajax/add.php
    ↓
Bitrix Sale Basket
```

## 2. Добавление товара

Используется:

```text
bitrix/components/znikolaj/searchparts/templates/.default/script.js
/ajax/add.php
```

При нажатии `.basketAdd` JavaScript передаёт:

```text
json — данные найденной запчасти
q    — количество
```

Запрос:

```text
GET /ajax/add.php
```

## 3. Что создаётся в корзине

`/ajax/add.php` использует:

```text
Bitrix\Sale\Basket
Bitrix\Sale\Fuser
```

Если такого товара ещё нет в корзине, создаётся:

```text
custom basket item
```

В него сохраняются:

```text
NAME
PRICE
QUANTITY
CURRENCY
ARTICLE
BRAND
```

Таким образом, в корзину можно добавить запчасть, которой нет в локальном каталоге Bitrix.

## 4. Повторное добавление

Если такой `custom` item уже есть в корзине, новое количество прибавляется к существующему.

Идентификатор товара формируется как:

```text
CUSTOM_ + md5(name + price)
```

Артикул и бренд в идентификатор не входят.

## 5. Важные особенности legacy

Цена передаётся из браузера и используется `/ajax/add.php` без повторного получения из источника.

Также серверная проверка остатка перед добавлением в корзину не обнаружена.

Это **особенности legacy**, а не требования новой системы.

## 6. После добавления

После сохранения корзины сервер возвращает HTML мини-корзины.

JavaScript обновляет:

```text
#btn_basket
```

Страница полностью не перезагружается.

## 7. Статус

Подтверждено:

```text
[✓] Результат поиска передаётся в корзину
[✓] Количество передаётся отдельно
[✓] Используется Bitrix Fuser
[✓] Используется Bitrix Sale Basket
[✓] Внешний товар может быть custom item
[✓] Сохраняются ARTICLE и BRAND
[✓] Повторное добавление увеличивает количество
[✓] Мини-корзина обновляется через AJAX

[ ] Исследован flow корзина → заказ
[ ] Проверено сохранение ARTICLE / BRAND в заказе
[ ] Исследовано дальнейшее оформление внешнего товара
```

## 8. Правило исследования

До завершения reverse engineering:

* production-код не изменять;
* корзины пользователей не изменять;
* заказы не создавать;
* данные в БД не изменять.

Исследование выполнять в read-only режиме.
