# 03. Исследование поиска запчастей и синхронизации каталога

## 03.1. Поиск запчастей

Поиск запчастей реализован кастомным компонентом Bitrix:

`/bitrix/components/znikolaj/searchparts/`

Основные файлы:

* `component.php` — серверная логика поиска;
* `templates/.default/template.php` — шаблон вывода;
* `templates/.default/script.js` — клиентская логика autocomplete;
* `templates/.default/style.css` — оформление.

### Autocomplete

При вводе артикула выполняется AJAX-запрос:

```text
POST /
ajax_call=y
INPUT_ID=search_input
q=341351
l=2
```

Ответом является HTML-блок с вариантами автодополнения.

### Полный поиск

При отправке формы выполняется:

```text
POST /search_parts/?q=341351
```

Результаты формируются сервером компонентом `znikolaj/searchparts`.

---

## 03.2. Источники данных при поиске

Компонент объединяет данные из нескольких источников.

### 1. Собственный склад

Собственный склад ищется непосредственно в Bitrix-инфоблоке:

```text
IBLOCK_ID = 11
Основной каталог товаров
IBLOCK_TYPE_ID = 1c_catalog
```

Поиск выполняется по свойству:

```text
PROPERTY_CML2_ARTICLE
```

Из Bitrix дополнительно используются:

```text
CATALOG_QUANTITY
CATALOG_PRICE_1
```

Для артикула `341351` найдена запись:

```text
ID: 45694
NAME: 341351 KAYABA амортизатор правой передней подвески MAZDA 6
CML2_ARTICLE: 341351
CATALOG_QUANTITY: 1
CATALOG_PRICE_1: 7240.00 RUB
```

Таким образом, собственный склад не требует обращения к внешнему API: данные берутся непосредственно из локального каталога Bitrix.

---

### 2. Adeo

Используется API:

```text
https://xml.adeo.pro/pricedetals2.php
```

Запрос выполняется методом `POST` и передаёт XML с параметрами поиска.

Без выбора конкретного производителя формируется список вариантов детали.

При выборе производителя формируется список конкретных предложений с:

* названием;
* артикулом;
* брендом;
* сроком поставки;
* наличием;
* ценой.

Цена проходит через функцию `getPrice()`.

---

### 3. Mikado

Используется SOAP API:

```text
https://www.mikado-parts.ru/ws1/service.asmx
```

Вызывается метод:

```text
Code_Search
```

Запрос выполняется по артикулу.

При выборе конкретного бренда результат фильтруется по производителю.

Из ответа используются:

* `Name`;
* `ZakazCode`;
* `ProducerBrand`;
* `DeliveryDelay`;
* `StockQTY`;
* `PriceRUR`.

Предложения дополнительно разделяются по типу кода:

* Aftermarket;
* AnalogOEM;
* Analog.

---

### 4. Автоконтинент

Используется API:

```text
api.autokontinent.ru
```

Сначала выполняется поиск детали по артикулу:

```text
/v1/search/part.json
```

Затем получаются цены:

```text
/v1/search/price.json
```

Используются:

* артикул;
* бренд;
* название;
* комментарий;
* срок доставки;
* количество;
* цена.

Предложения разделяются на оригинальные номера и аналоги.

---

## 03.3. Наценка

Для внешних поставщиков цена не используется напрямую.

В Bitrix-инфоблоке `14` хранятся проценты наценки в формате:

```text
market=percent
```

Например, компонент загружает эти значения и применяет:

```text
цена = исходная цена × (1 + наценка / 100)
```

Для собственного склада используется непосредственно цена из каталога Bitrix:

```text
CATALOG_PRICE_1
```

# 03.4. Синхронизация каталога с 1С

Каталог Bitrix:

```text
IBLOCK_ID = 11
NAME = Основной каталог товаров
IBLOCK_TYPE_ID = 1c_catalog
```

Синхронизация выполняется через стандартный механизм CommerceML Bitrix.

Основной endpoint:

```text
/bitrix/admin/1c_exchange.php
```

В системе присутствует стандартный Bitrix importer CommerceML:

```text
bitrix/modules/sale/admin/1c_exchange.php
bitrix/modules/catalog/load_import/commerceml_run.php
```

Дополнительно обнаружены стандартные файлы запуска импорта в:

```text
bitrix/php_interface/include/catalog_import/
```

---

## 03.5. Фактический обмен

На сервере сохранены реальные отчёты обмена:

```text
upload/1c_catalog/Reports/
```

Отчёты присутствуют как минимум за:

```text
30.08.2026
31.08.2026
01.09.2026
02.09.2026
03.09.2026
04.09.2026
```

Таким образом, подтверждён ежедневный обмен.

На примере 04.09.2026 обмен начался:

```text
23:00:00
```

и завершился:

```text
23:04:05
```

В рамках одного обмена последовательно передаются:

```text
23:00:07  import
23:01:57  import
23:02:13  offers
23:03:08  prices
23:04:02  rests
```

Все файлы получили статус:

```text
success
```

## 03.6. Кто инициирует синхронизацию

По совокупности обнаруженных данных синхронизация определяется как схема:

```text
1С
 ↓
CommerceML
 ↓
/bitrix/admin/1c_exchange.php
 ↓
Bitrix CommerceML importer
 ↓
Инфоблок каталога / каталог товаров
```

То есть **1С является инициатором обмена, а сайт выступает принимающей стороной**.

Прямой access-log HTTP-запроса от 1С за конкретный обмен на сервере не сохранился, поэтому IP-адрес клиента непосредственно подтвердить не удалось. Однако найденный endpoint, формат CommerceML, последовательность файлов и реальные отчёты обмена соответствуют стандартной схеме 1С → Bitrix.

---

## 03.7. Полный обмен или только изменения

Для файла остатков:

```text
rests___10abf225-f8cd-4131-a900-45b44a4b8990.xml
```

непосредственно найдено:

```xml
<ПакетПредложений СодержитТолькоИзменения="true">
```

Следовательно:

**остатки передаются инкрементально — только изменившиеся данные.**

Для файлов:

```text
import
offers
prices
```

по имеющимся серверным артефактам пока нельзя достоверно определить, являются ли они полными или инкрементальными.

Сами XML-файлы после обработки Bitrix на сервере не сохраняются. В `upload/1c_catalog` на момент исследования сохранился только `rests___*.xml`.

## 03.8. Текущая установленная схема

На данный момент схема текущего сайта выглядит следующим образом:

```text
                         ┌─────────────────┐
                         │       1С        │
                         └────────┬────────┘
                                  │
                         CommerceML / HTTP
                                  │
                                  ▼
                    ┌─────────────────────────┐
                    │   Bitrix 1C exchange    │
                    │ /bitrix/admin/1c_exchange│
                    └────────────┬────────────┘
                                 │
                         CommerceML importer
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │    Bitrix каталог       │
                    │       IBLOCK 11         │
                    └────────────┬────────────┘
                                 │
                  ┌──────────────┴──────────────┐
                  │                             │
                  ▼                             ▼
          собственный склад              поиск запчастей
          цена + остаток                 + внешние API
```

### Зафиксированные факты

* каталог товаров — Bitrix IBLOCK `11`;
* синхронизация выполняется через CommerceML;
* инициатором считается 1С;
* подтверждён ежедневный обмен около 23:00;
* один обмен содержит `import`, `offers`, `prices`, `rests`;
* остатки передаются только изменениями;
* собственный склад читается непосредственно из Bitrix;
* внешние предложения при поиске запрашиваются напрямую из Adeo, Mikado и Автоконтинента;
* цены внешних поставщиков проходят через механизм наценки Bitrix.
