# Японец

Сайт магазина запчастей для японских и корейских автомобилей.

## Структура проекта

- [`frontend/`](frontend/) — приложение на React, TypeScript и Vite: исходники, статические файлы, зависимости и настройки сборки.
- [`docs/`](docs/) — общие требования, сценарии, дизайн и планы развития системы.
- [`legacy/`](legacy/) — исследовательские материалы о предыдущем сайте.

Бэкенд пока не реализован. Для будущего сервиса на Go предусмотрена отдельная папка `backend/` рядом с `frontend/`.

## Запуск фронтенда

Из корня репозитория:

```bash
cd frontend
npm install
npm run dev
```

Сборка: `npm run build` из `frontend/`. Результат появится в `frontend/dist/`.

Подробные команды и инструкция по настройке контента: [`frontend/README.md`](frontend/README.md).

## Запуск на сервере через Docker Compose

Нужны Docker Engine и Docker Compose. Из корня скопированного на сервер репозитория:

```bash
docker compose up -d
```

При первом запуске Compose соберёт образ `japandetali-frontend:local`: Node.js установит зависимости через `npm ci` и соберёт фронтенд, затем Nginx будет раздавать готовый сайт на порту **80**. Node.js на сервер устанавливать не нужно. Секреты, локальные зависимости и документация исключены из контекста сборки.

Если на сервере используется отдельная команда Compose, эквивалентный запуск — `docker-compose up -d`.

Для другого порта создайте `.env` рядом с `docker-compose.yml`:

```dotenv
HTTP_PORT=8080
```

Сайт будет доступен по адресу `http://<IP-сервера>:8080`. Для размещения за обратным прокси на том же сервере добавьте `HTTP_BIND_ADDRESS=127.0.0.1`. HTTPS настраивается на обратном прокси; контейнер обслуживает HTTP.

Обновление после получения новой версии исходников:

```bash
docker compose up -d --build
```

Проверка состояния, просмотр логов и остановка:

```bash
docker compose ps
docker compose logs --tail=100 -f
docker compose down
```

Контейнер перезапускается после сбоя или перезагрузки сервера, если запущен Docker. Проверка `/healthz` показывает работоспособность Nginx; статус `unhealthy` сам по себе не вызывает перезапуск.

### Контакты и настройки без пересборки

По умолчанию `site-settings.json` входит в образ. Для независимого редактирования и сохранения настроек между обновлениями один раз подготовьте каталог:

```bash
mkdir -p deploy
cp frontend/public/site-settings.json deploy/site-settings.json
```

Создайте `docker-compose.override.yml` рядом с основным Compose-файлом:

```yaml
services:
  frontend:
    volumes:
      - ./deploy:/usr/share/nginx/html/settings:ro
```

Добавьте в `.env`:

```dotenv
VITE_SITE_SETTINGS_URL=/settings/site-settings.json
```

Примените конфигурацию командой `docker compose up -d --build`. Затем редактируйте `deploy/site-settings.json`: после обновления страницы посетители увидят изменения. Каталог подключён целиком, поэтому замена файла редактором тоже будет видна контейнеру. `.env`, `deploy/` и локальный override исключены из Git; сохраняйте резервные копии настроек отдельно.

Для внешнего хранилища в `VITE_SITE_SETTINGS_URL` можно указать полный URL. Эта переменная применяется **при сборке**, поэтому изменение URL требует `docker compose up -d --build`.
