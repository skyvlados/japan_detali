# Японец — frontend

Сайт-визитка магазина запчастей для японских и корейских автомобилей. Frontend собран на React, TypeScript и Vite.

## Требования

- Node.js 20 или новее
- npm

Проверить установленные версии:

```bash
node --version
npm --version
```

## Первый запуск

```bash
cd /Users/vladislav/Repositories/japandetali_next/frontend
npm install
npm run dev
```

После запуска открыть адрес, показанный в терминале. Обычно это:

```text
http://localhost:5173/
```

Остановить локальный сервер: `Ctrl+C`.

## Повторный запуск

Если зависимости уже установлены:

```bash
cd /Users/vladislav/Repositories/japandetali_next/frontend
npm run dev
```

## Production-сборка

Создать оптимизированную сборку:

```bash
npm run build
```

Результат появится в папке `dist/`.

Проверить production-сборку локально:

```bash
npm run preview
```

## Основные файлы

- `src/App.tsx` — структура страницы и контент;
- `public/site-settings.json` — контакты и адреса магазинов;
- `src/styles.css` — стили и адаптивная вёрстка;
- `public/logo.svg` — логотип;
- [`../docs/`](../docs/) — требования, структура контента и дизайн-направление.

Все команды и пути в этой инструкции указаны относительно папки `frontend/`.

## Инструкция по site-settings.json

Файл `public/site-settings.json` содержит все изменяемые контакты, реквизиты и данные магазинов. Сайт загружает его при открытии страницы. Изменения не требуют пересборки или перезапуска сайта.

### Где редактировать

- При локальной разработке — `public/site-settings.json`.
- На сервере — `site-settings.json` в корне опубликованного сайта. При сборке он копируется в `dist/site-settings.json`.
- Если настроено внешнее хранилище — файл по адресу `VITE_SITE_SETTINGS_URL`.

### Полный пример

Все контакты и реквизиты ниже — примеры для замены на реальные данные. Для Telegram выберите номер или ник своего менеджера.

```json
{
  "contacts": {
    "phones": ["+7 (812) 000-00-00", "+7 (812) 000-00-01"],
    "whatsappPhone": "+7 (900) 000-00-00",
    "telegramPhone": "@manager_name",
    "messageText": "Здравствуйте! Нужен подбор запчасти.\n\nАвтомобиль: …\nГод: …\n\nVIN/номер кузова или артикул: …",
    "email": "info@yaponets.example",
    "emailHref": "mailto:info@yaponets.example"
  },
  "legal": {
    "name": "ИП Иванов Иван Иванович",
    "inn": "000000000000",
    "ogrn": "0000000000000"
  },
  "stores": [
    {
      "id": "central",
      "name": "Магазин в Санкт-Петербурге",
      "address": "Санкт-Петербург, Невский проспект, 1",
      "addressConfirmed": true,
      "pavilion": "12А",
      "workingHours": "Пн–Пт: 10:00–19:00\nСб–Вс: выходной",
      "directions": "Вход со стороны парковки"
    }
  ]
}
```

### Телефоны, Telegram и WhatsApp

| Поле в `contacts` | Что указать и где используется |
| --- | --- |
| `phones` | Список из одного или нескольких телефонов. Все видны в шапке, мобильном меню и контактах. Первый используется кнопками «Позвонить» на первом экране и в мобильной панели. |
| `whatsappPhone` | Отдельный номер WhatsApp, например `+7 (900) 000-00-00`. |
| `telegramPhone` | Номер Telegram, например `+7 (900) 000-00-01`, либо ник `@manager_name` / `manager_name`. Название поля одинаковое для обоих вариантов. |
| `messageText` | Общий черновик сообщения для Telegram и WhatsApp. Можно менять текст, использовать `\n` для переноса строки. Пустое или отсутствующее поле отключает предзаполнение. |
| `email` | Почта, отображаемая на странице. |
| `emailHref` | Ссылка для почтовой программы: `mailto:info@yaponets.example`. При смене почты обновите и `email`, и `emailHref`. |

Номера задаются независимо. Для второго телефона добавьте ещё одну строку в список `phones` через запятую. Чтобы убрать номер, удалите его из списка; оставьте хотя бы один.

Указывайте международный номер с кодом страны: для России `+7`, а не `8`. Пробелы, скобки и дефисы допустимы. Ссылки формируются автоматически:

- номер `+7 (900) 000-00-01` для Telegram → `https://t.me/+79000000001`;
- ник `@manager_name` или `manager_name` → `https://t.me/manager_name`;
- номер WhatsApp → `https://wa.me/79000000001`.

В `telegramPhone` указывайте именно username из профиля, а не отображаемое имя и не полную ссылку. Для перехода по номеру менеджер должен разрешить поиск по номеру в настройках Telegram. В WhatsApp номер должен быть зарегистрирован.

«Написать менеджеру» в шапке и «Написать» в мобильной панели открывают выбор мессенджера. Кнопки в контактах ведут сразу в сервис. Приложение или веб-страницу открывает браузер в зависимости от устройства и установленных приложений. Текст из `messageText` передаётся в поле ввода как черновик; посетитель дополняет его и отправляет сам. Для Telegram это работает и с номером, и с ником. Если конкретный клиент не подставляет текст, проверьте переход в актуальном приложении Telegram. Сообщения автоматически не отправляются.

### Раздел «О компании»

Блок `about` управляет текстом раздела «О компании» и плашкой стажа. Изменения загружаются из JSON после обновления страницы, как контакты.

| Поле | Что менять |
| --- | --- |
| `eyebrow` | Короткая подпись над заголовком. |
| `title` | Основной заголовок. |
| `paragraphs` | Список абзацев: каждый элемент — отдельная строка текста в кавычках. Нужен хотя бы один абзац. |
| `highlights` | Список преимуществ с полями `title` и `text`. Пустой список `[]` скрывает преимущества. |
| `experienceValue` | Короткое значение на плашке, например `20+`. |
| `experienceLabel` | Подпись на плашке, например `лет опыта`. |

Используйте обычный текст без HTML. Все поля блока обязательны. Если весь `about` отсутствует в старом JSON, используется резервный текст из `src/about.ts`. Блок не меняет название бренда, текст первого экрана или список марок в других секциях.

Текст адаптирован по [странице действующего сайта](https://japandetali.ru/about/): стаж, направления подбора, склад, категории деталей и доставка. На исходной странице используется название «Автодог», в новом сайте сохранено текущее название «Японец».

### Реквизиты

Блок `legal` отображается внизу подвала:

| Поле | Значение |
| --- | --- |
| `name` | Полное название, например `ИП Иванов Иван Иванович`. |
| `inn` | ИНН, строка в кавычках. |
| `ogrn` | ОГРН, строка в кавычках. |

Замените временные реквизиты с нулями перед публикацией. Если реквизиты не нужны, удалите весь блок `legal`. Все поля необязательны: отсутствующие и пустые значения скрываются. Если заполненных полей нет, весь блок скрывается.

### Магазины, павильон, график и карта

Каждый объект в списке `stores` создаёт отдельную карточку магазина. Для второй точки скопируйте объект внутри списка, разделите объекты запятой и задайте другой `id`. Оставьте хотя бы один магазин.

| Поле магазина | Назначение |
| --- | --- |
| `id` | Обязательный уникальный идентификатор, например `central`. |
| `name` | Обязательное название карточки. |
| `mapUrl` | Необязательная HTTPS-ссылка на карточку магазина в Яндекс Картах (через «Поделиться», например `https://yandex.ru/maps/-/...`). Кнопка «Открыть Яндекс Карты» и ссылка под мини-картой открывают её. Без поля или при пустой строке используется поиск по адресу. Отображением входов управляют Яндекс Карты. |
| `address` | Обязательный полный адрес с городом, домом и корпусом. Используется в тексте, поиске Яндекс Карт и маршруте. |
| `addressConfirmed` | `true` — адрес уточнён, кнопка маршрута видна; `false` — показано предупреждение об уточнении адреса, маршрут скрыт. Пишите без кавычек. |
| `pavilion` | Необязательный номер, например `"12А"`: появится «Павильон 12А». Пустое `""`, пробелы или отсутствие поля полностью скрывают строку. |
| `workingHours` | График, например `"10:00–19:00"`. Для нескольких строк используйте `\n`, как в полном примере. Если поле пустое или отсутствует, будет показана просьба уточнить график. |
| `directions` | Необязательная подсказка о входе или проезде. Удалите поле или оставьте `""`, чтобы скрыть текст. |

Для маршрута в мобильных Яндекс Картах добавьте в объект магазина `coordinates`: объект с числовыми полями `latitude` (широта от −90 до 90) и `longitude` (долгота от −180 до 180). Возьмите точные координаты входа в магазин из Яндекс Карт. Маршрут передаёт эти координаты как конечную точку; начальную точку определяют Яндекс Карты. Без координат сохраняется маршрут по адресу для совместимости, но мобильное приложение может его не распознать.

При переезде обновите `address`, `coordinates` и при необходимости `mapUrl`. Мини-карта использует поиск по адресу, ссылка на полную карту — `mapUrl`, если он задан. Павильон выводится отдельно и не меняет запрос карты. После смены адреса проверьте, что Яндекс верно распознал дом и корпус.

### Как обновить файл на сервере

1. Сохраните копию текущего `site-settings.json`.
2. Измените нужные значения, сохранив структуру JSON.
3. Замените файл на сервере по тому же пути.
4. Обновите страницу сайта: уже открытая страница не перечитывает настройки автоматически.
5. Проверьте изменённые данные и соответствующие кнопки.

Для `/site-settings.json` отключите кеширование на сервере/CDN. Сайт сам запрашивает файл без браузерного кеша, но настройки прокси и CDN задаются отдельно.

Обычный деплой может перезаписать ручные изменения файлом из `dist`. Чтобы сохранить настройки между деплоями, настройте сервер на выдачу `/site-settings.json` из отдельного постоянного каталога либо используйте внешнее хранилище.

Для внешнего хранилища задайте `VITE_SITE_SETTINGS_URL`, например `https://content.example.com/site-settings.json`, **при сборке**. Сервер файла должен разрешать CORS для домена сайта. Изменение URL требует новой сборки; изменение содержимого файла по прежнему URL — нет. Бэкенд для редактирования JSON не нужен.

### Если после изменения сайт не загружается

Файл должен быть доступен по настроенному URL и содержать корректный JSON. При ошибке сайт показывает сообщение с кнопкой повторной загрузки.

Проверьте:

- все названия полей и текстовые значения заключены в двойные кавычки;
- между полями и элементами списка есть запятые, после последнего элемента запятой нет;
- внутри JSON нет комментариев;
- номера телефонов, ИНН и ОГРН записаны строками в кавычках;
- обязательные поля заполнены, списки `phones` и `stores` не пустые;
- Telegram указан номером или ником, без URL и пробелов внутри ника.

Синтаксис локального файла можно проверить из каталога проекта:

```bash
node -e 'JSON.parse(require("node:fs").readFileSync("public/site-settings.json", "utf8")); console.log("JSON корректен")'
```

Эта команда проверяет только синтаксис JSON, а не существование аккаунтов или правильность значений. Если ошибку не удаётся найти, восстановите сохранённую копию и обновите страницу.

Файл публичный: храните в нём только данные, предназначенные для посетителей, без паролей и ключей.

### Совместимость со старыми настройками

Старый `contacts.phoneLabel` поддерживается как один общий номер, если новые поля ещё не заданы. Для новых настроек используйте `phones`, `whatsappPhone` и `telegramPhone`. Старые вычисляемые ссылки `phoneHref`, `whatsapp`, `telegram` и поле магазина `mapPoint` больше не нужны.
